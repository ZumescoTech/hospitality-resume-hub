## 1. Checker rejects non-CV documents (22 Oct, ISSUE-018)

**Problem:** the checker gave an ATS score to almost any document, such as a cover letter or an invoice.

**What changed:**
- A validation gate runs before scoring (and before the score cache, so a cached score can't bypass it). It classifies the text as **valid CV**, **uncertain** or **not a CV**, using contact details, section headings, date ranges, job-role words and bullet lists. It doesn't rely on the file name or the word "CV". No AI call is involved.
- **Not a CV:** no score. The page gives the reason, plus **Start a CV from scratch** and **Try again with a different file**.
- **Uncertain:** no score until the user clicks **Yes, this is my CV — check it**.
- Short beginner CVs are still accepted.
- Scores for real CVs are unchanged.

**How to test:**
1. Upload a cover letter, invoice or bank statement to `/tools/cruise-cv-checker`. You should get no score, a reason, and the two buttons.
2. Upload a short one-page beginner CV. It is scored normally.
3. Upload a real CV. Its score matches what it was before.

**Tests:** `cv-document-classifier.test.ts` (39 pass) and `check-cruise-cv-document-gate.test.ts` (9 pass). They use synthetic CVs and non-CVs in `tests/fixtures/documents/`.

## 2. Import CV no longer fails when AI is down

**Problem:** importing a CV showed `[provider] exhausted: Both providers failed`.

**Root cause:** both AI models had been retired (see item 5). Separately, the builder had no fallback, so any AI failure blocked the import.

**What changed:**
- If both AI providers fail, the import falls back to the built-in local parser, so the CV still loads.
- Server logs now record *why* each provider failed (status and error text). API keys are hidden and CV text is never logged.

**How to test:**
1. In the builder, click **Import CV** and choose a CV file.
2. The CV fills the form with no red error message.
3. On `/tools/logs`, a line `[ai-router] groq ok …` means the AI parsed it. A line `[parse-cv] … using local parse` means the fallback was used.

## 4. Temporary logs page — `/tools/logs`

**What it does:** shows server logs and browser errors from the last 3 days, newest first. You can filter by level (errors/warnings), by source (server/browser) and by search text, and turn on auto-refresh every 10s.

- **Captured:** every server `console.log`, `console.warn` and `console.error`, and unhandled request errors. From the browser: uncaught errors, failed promises, `console.warn`/`console.error` and every red error toast.
- **Privacy:** emails, phone numbers and API keys are replaced before saving. Entries delete themselves after 3 days.
- **Open to anyone** (your choice). The page is hidden from search engines.

**How to test:**
1. Open `https://<your-site>/tools/logs`.
2. In another tab, use the builder (import a CV, for example).
3. Wait about a minute, then click refresh on the logs page. New entries appear.

**To turn it off:** set `DEBUG_LOGS_ENABLED` to `"false"` in `wrangler.jsonc` and deploy.
**To remove it entirely:** delete `src/start.ts`, `src/lib/debug-log.ts`, `src/lib/debug-log-api.ts`, `src/lib/client-log-capture.ts`, `src/routes/tools/logs.tsx`, `tests/unit/debug-log.test.ts`, the `client-log-capture` line in `src/routes/__root.tsx`, and the `DEBUG_LOGS_ENABLED` line in `wrangler.jsonc`.

**Note:** saved logs use Cloudflare KV's free tier, about 1,000 writes a day. Heavy traffic could use that up, which is another reason to remove the page when you're done.

## 5. AI models replaced

**Problem (found with the logs page):**
- Groq returned 404: `llama-3.3-70b-versatile` was shut down on 16 Aug 2026.
- Gemini returned 404: `gemini-2.5-flash` is no longer available to new users.

**What changed:**

| Provider | Old | New |
|----------|-----|-----|
| Groq (primary) | `llama-3.3-70b-versatile` | `openai/gpt-oss-120b` |
| Gemini (fallback) | `gemini-2.5-flash` | `gemini-3.8-flash` |

- All Groq calls now use one shared model setting, `GROQ_MODEL` in `src/lib/ai/groq-client.ts`, so a future change happens in one place.
- Both new models "think" before answering, so thinking is set to low. Otherwise the thinking uses up the reply length and cuts off the JSON.
- Scores are unaffected: the AI never sets numeric scores, and the golden-file tests are unchanged.

**How to test:**
1. Import a CV in the builder.
2. `/tools/logs` shows `[ai-router] groq ok`. This was already confirmed on the live site.

## 6. Download PDF now matches the preview

**Problems:**
- Download PDF used a separate PDF engine (react-pdf) with its own layouts, so the file didn't match the preview.
- That engine logged `Buffer is not defined` every time you moved the photo.
- The printer icon printed the whole builder page, editor included.

**What changed:**
- The separate PDF engine is removed.
- Download PDF opens the browser's print window on a hidden, full-size copy of the preview: same template, colours, photo position and formatting. Only that copy prints, on A4.
- The file name defaults to `Your_Name_CV`.
- The printer icon is removed.
- The text in the PDF stays selectable, so applicant tracking software can read it.

**How to test:**
1. In the builder, load your CV and pick a template.
2. Click **Download PDF**: top-right of the preview on desktop, or the green **Download** bar on a phone.
3. In the print window, choose **Save as PDF** and save.
4. Open the PDF. It should look the same as the preview, with no editor, buttons or menus.
5. Repeat with a few templates, including **Noir** and **Harbour**.
6. Move the photo position. `/tools/logs` no longer shows `Buffer is not defined`.

**Things to know:**
- Users must choose **Save as PDF** in the print window. That's the trade-off for an exact match.
- Only a one-page CV was tested. A longer CV flows onto page 2, but the page break hasn't been checked.
- The page-margin setting in Customize doesn't change the PDF. The preview never used it either.

## 8. "Customise CV to this job"

**What it does:** a green button under **Target job ad**. It rewrites your **professional summary** and **experience bullet points** to match the pasted job ad. It uses the ad's keywords (Opera PMS, Micros, WSET…) where your CV already supports them, and puts the most relevant achievements first.

**What it will never do** (enforced in code, not just in the AI's instructions):
- Change job titles, employers, dates, education or certificates.
- Add numbers you didn't write. Any new figure becomes `[X]` for you to fill in.
- Add skills you haven't confirmed. Suggested skills are tick-boxes; only the ones you tick are added.

**Other behaviour:**
- The button is greyed out until a job ad is pasted, and shows "Customising your CV…" while it runs.
- **Review before applying:** a window shows your current text next to the suggested text for the summary and each changed job, plus how many `[X]` placeholders need figures. **Nothing changes until you click Apply changes.** "Keep my original" closes it with no changes.
- After applying, a message has an **Undo** button that restores your CV as it was.
- If the AI is unavailable, your CV stays unchanged and you're asked to try again. It tries Groq first, then Gemini.

**How to test:**
1. In the builder, load your CV (or the example CV).
2. Paste a real job ad into **Target job ad**. The button turns from grey to green.
3. Click **Customise CV to this job** and wait a few seconds. The review window opens.
4. In the review window:
   - Compare **Now** and **Suggested** for the summary and each job.
   - Job titles, employers and dates must be unchanged.
   - Tick only the skills you genuinely have.
5. Click **Keep my original** first. Nothing in your CV should change.
6. Click the button again, then **Apply changes**. The CV updates, and only the ticked skills are added.
7. Fill in any `[X]` placeholders with your real figures.
8. Click **Undo** in the message. Your original text comes back.
9. On `/tools/logs`, you should see `[tailor-cv] request` followed by `[ai-router] groq ok`.

**Not yet tested:** a real AI rewrite. There were no API keys locally, so only the button, the disabled state and the failure path were tested in the browser. The merge logic, safety rules and review window are covered by unit tests.

## 9. MVP brief fixes

These four came from checking the app against *Get Hired MVP Release Brief v1.0 (14 Oct 2026)*.

### 9a. The score is labelled as an internal indicator (brief §3B)

**Problem:** the checker called it "ATS Score" with no explanation, and the landing page said it used "real cruise line hiring criteria". Users could read that as an official cruise-line score.

**What changed:**
- The ring now says **CV readiness**.
- A line under it explains that it is GetHired's internal guide to how ready the CV is for the role. It is based on role keywords, experience detail, measurable results, how easily ATS software can read the CV, and the summary. It is **not a cruise line's official ATS score or a prediction of being hired**.
- Landing page copy updated to match ("CV readiness score", "the keywords, experience and results cruise and hotel roles ask for").

**How to test:**
1. Run a CV through `/tools/cruise-cv-checker`.
2. The ring says **CV readiness**, and the explanation sits under the band label.
3. On the landing page, step 02 says "Get your CV readiness score".

### 9b. "Not mentioned" is never shown as "does not have" (brief §3B)

**Problem:** the builder's wine and spirits dropdowns showed **"None"** when the CV didn't mention them. That reads as "has no wine knowledge". The checker also said "Hard requirements missing".

**What changed:**
- The builder shows **"Not stated"** instead of "None". The stored value is unchanged, so no data or score changes.
- The AI extraction prompt now defines "None" as *not stated in the CV* and tells the AI never to infer the candidate lacks it.
- Checker wording:
  - "Hard requirements missing" → "Hard requirements not shown on your CV".
  - "Scored against real cruise recruiter standards" → "Checked against what cruise and hotel roles ask for".
  - A new note under missing keywords: "Not mentioned isn't the same as not having it — if you have these, add them to your CV."

**How to test:**
1. In the builder, open **Hospitality** on an empty CV. Wine and spirits show **Not stated**.
2. In the checker results, the keyword section shows the "Not mentioned isn't the same…" note.

### 9c. Job tailoring is reviewed before it applies (brief §3B/§3C)

See item 8: the review window and opt-in skill tick-boxes.

### 9d. Automated PDF read-back test (brief §3C)

**Problem:** the brief asks to "test PDF parsing". The old PDF engine's tests were removed with that engine, so nothing checked the new PDF output automatically.

**What changed:** a new test, `tests/e2e/pdf-export.spec.ts`. For each of the 7 templates it loads the example CV, prints exactly as Download PDF does, reads the PDF text back with pdf.js, and checks:
- exactly one page;
- the name, job title, employer and WSET certificate are real, selectable text;
- reading order is name, then summary, then work history;
- no builder UI is in the file ("Download PDF", "Customize", "Target job ad", "Personal details", "Import CV").

**Result:** 7/7 pass on Chromium.

**How to run it:**
```bash
npm run build
npx wrangler dev --local --config dist/server/wrangler.json --port 8788
BASE_URL=http://localhost:8788 npx playwright test pdf-export --project=chromium
```
Run the second command in its own terminal and leave it running. If Playwright says its browser is missing, run `npx playwright install chromium`, or set `CHROME_EXE` to an installed Chromium.
